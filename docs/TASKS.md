**2026-08-19 / `NO_OPENAPI_SERVICE_ERROR`(코드 12) / 오퍼레이션명 오류 / 해결**

**2026-08-22 / db 테스트가 실서비스에 데이터를 남길 위험 / 설계로 회피**
이 Supabase 는 다른 3개 프로젝트와 공유되는 실서비스다. 적재 테스트가 흔적을 남기면 안 된다.
→ db 테스트는 **`autocommit=False` 연결에서 돌리고 teardown 에서 `rollback()`** 한다.
전량 e2e(6,910건) 확인도 같은 방식으로 했고, 이후 `onbid_cltr` 행수 0·`T-%` 잔여 0 을 확인했다.

**2026-08-22 / `scripts/` 를 타입 체크에 넣자 37건 오류 / 변수 재사용이 원인**
프로브 스크립트를 mypy 대상에서 빼 두었다가 뒤늦게 포함했더니, 같은 함수 안에서
**한 변수를 다른 타입으로 재사용**한 곳이 여럿 나왔다(`got` 이 int 와 list, `it` 이 list 와 dict).
동작에는 문제가 없었지만 읽는 사람을 헷갈리게 하는 코드다.
→ 예외를 두지 않고 전부 고쳤다. 검증 명령에 `scripts/` 를 상시 포함한다.

**2026-08-22 / db 테스트가 연속 실행에서만 실패 / 트랜잭션 풀러 / 해결**
`SUPABASE_DATABASE_URL` 이 **pgbouncer 트랜잭션 풀러(6543)** 를 가리키는데, psycopg 는
같은 쿼리가 반복되면 자동으로 prepared statement 로 전환한다. pgbouncer 는 이를 지원하지 않아
**단독 실행은 통과하고 전체 실행에서만 깨졌다** — 원인 찾기가 가장 어려운 형태다.
→ 연결에 `prepare_threshold=None`. SPEC C10 으로 명문화했고 store 계층에도 같이 적용한다.
곁들여 `autocommit=True` 도 켰다 — 트랜잭션 안에서 한 쿼리가 실패하면 이후 전부
"current transaction is aborted" 가 되어 진짜 원인이 가려진다.

**2026-08-22 / Red 미실행 → 돌연변이 검사로 사후 보완 / 구멍 1건 발견**
M2 에서 테스트는 구현보다 먼저 썼으나 **실패를 실행으로 확인하지 않았다**(CLAUDE.md TDD 의 Red 는
"실패 확인"까지 포함). Red 의 실질은 "테스트가 헛돌지 않는지" 보는 것이므로, 사후에
핵심 로직을 일부러 훼손해 테스트가 잡는지 검사했다.

7건 중 **6건은 잡았고 1건을 놓쳤다** — `UsageIndex.descendants` 의 재귀를 1단계로 줄여도
전부 통과했다. 테스트 트리가 3단인데 **2단 이상 재귀를 검증하는 케이스가 없었다.**
대분류로 검색하면 소분류 물건을 놓치는 실제 결함으로 이어질 수 있었다.

**교훈**: Red 를 건너뛰면 "통과하지만 아무것도 검증하지 않는" 테스트가 남는다.
