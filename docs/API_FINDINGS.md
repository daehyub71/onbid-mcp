>
> 덤으로 확인된 것: **수의계약 그룹(1,143건)은 전원이 유찰 1회 이상**이다. 수의계약이 유찰 뒤에 열리는 제도라는 점과 맞아떨어진다 — 그룹 분리(F1.9)와 대상 제외(F1.11)가 같은 사실을 가리킨다.

`apslPrcCtrsLowstBidRto`(감정가 대비 현재 최저입찰가), `frstCtrsLowstBidPrcRto`, `feeRate` —

→ **최저가율은 자체 계산한다**: `lowstBidPrcIndctCont / apslEvlAmt`
→ **계산 가능률 95.0%** (5,856건). 나머지는 감정가 결측(4.9%)과 최저가 비수치(0.02%).

### ② 코드표 명칭과 응답 명칭이 다르다

`bidDivCd=0001`을 코드표는 **"인터넷"**, 응답 `bidDivNm`은 **"전자입찰"** 이라 한다.
→ **표시용 명칭은 코드표가 아니라 응답의 `*Nm` 필드를 사용한다.**

### ③ 입찰일시에 `2999` sentinel이 있다

`cltrBidBgngDt`/`cltrBidEndDt`가 `299901021000` 형태로 오는 경우가 **18건(0.3%)** 있다. 일정 미정을 뜻한다.
그대로 저장하면 마감일 정렬·필터가 오염된다.
→ `bid_start`/`bid_end`를 **null**로 두고 `bid_date_tbd=1` 플래그로 표시한다.

### ④ 날짜 포맷이 필드마다 다르다

| 필드 | 포맷 |
|---|---|
| `cltrBidBgngDt` / `cltrBidEndDt` | `yyyyMMddHHmm` (12자리) |
| `mdfcnDt` | `yyyyMMddHHmmss` (14자리) |
| `dtbtRqrEdtmCont` | **`yyyy/MM/dd`** (슬래시 구분) |

전부 타임존 표기가 없다. **KST로 간주**한다.

### ⑤ 최저입찰가는 숫자가 아닐 수 있다

`lowstBidPrcIndctCont`는 `VARCHAR`이며 실제로 **`"비공개"`** 문자열이 관측된다.
빈도는 6,161건 중 **1건(0.02%)** 으로 매우 드물지만, 정수 캐스팅 시 예외가 난다.
→ 파싱 실패 시 `min_bid_amt`는 null, 원문은 `min_bid_amt_text`에 보존한다.

### ⑥ PNU 결측률이 낮지 않다

| 필드 | 결측률 |
|---|---|
| `ltnoPnu` (지번PNU) | **28.9%** |
| `rdnmPnu` (도로명PNU) | **36.2%** |

→ **PNU는 지오코딩을 대체하지 못한다.** 다만 `lctnEmdNm`(읍면동)이 **결측 0%** 이므로
`시도+시군구+읍면동` 조합 폴백은 항상 성립하며, **좌표 산출 실패(`failed`)는 원리적으로 발생하지 않아야 한다.**

## 인증키 모델 — "계정당 1개" 가 아니다 (2026-08-23 실측)

재발급 후 세 개의 키를 두 게이트웨이에 각각 호출해 본 결과다.

| 키 | 온비드 (`apis.data.go.kr`) | odcloud (`api.odcloud.kr`) |
|---|---|---|
| 재발급 **전** 키 (노출 이력 있음) | ✅ `00 NORMAL_CODE` | ❌ HTTP 401 |
| 청약 뉴스레터가 쓰던 키 | ❌ `30 SERVICE_KEY_IS_NOT_REGISTERED` | ✅ HTTP 200 |
| **재발급 후 새 키** | ✅ `00 NORMAL_CODE` | ✅ HTTP 200 |

**두 가지가 통념과 다르다.**

1. **키가 계정당 하나가 아니다.** 세 키가 동시에 유효하며, 각자 통하는 게이트웨이가 다르다.
   `30 SERVICE_KEY_IS_NOT_REGISTERED` 는 "키가 죽었다" 가 아니라 **"이 서비스에는 등록되지
   않은 키다"** 로 읽어야 한다 — 키 폐기 여부를 이 코드로 판단하면 틀린다.
2. **재발급이 기존 키를 폐기하지 않는다.** 새 키가 발급될 뿐이고, 노출된 구 키는 온비드에
   대해 **여전히 정상 응답**한다. 유출 대응(N4.2)은 재발급만으로 끝나지 않으며 **구 키 폐기가
   따로 필요**하다.

> 키가 살아 있는지 확인할 때는 **실제로 쓰는 게이트웨이에 호출**해 봐야 한다. 다른 서비스의
> 응답으로 유추하면 두 방향 모두 틀릴 수 있다.

멱등이라(AC2) 손해가 없다.
